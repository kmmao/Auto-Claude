# 翻译脚本问题总结与解决方案

## 问题根源

我创建的 `translate-content.cjs` 脚本存在一个系统性问题:它使用简单的字符串替换,无法区分不同的 JavaScript/TypeScript 上下文。

### 问题表现

脚本会将所有匹配的字符串替换为 `{t("key")}`,但这在不同上下文中会导致语法错误:

1. **对象字面量中** ❌
   ```typescript
   // 错误
   { label: {t("settings:appearance.title")} }
   // 正确
   { label: t("settings:appearance.title") }
   ```

2. **JSX 属性中** ❌
   ```typescript
   // 错误
   title=t("common:buttons.save")
   // 正确
   title={t("common:buttons.save")}
   ```

3. **JSX 表达式中嵌套** ❌
   ```typescript
   // 错误
   ({name || {t("default")}})
   // 正确
   ({name || t("default")})
   ```

## 为什么一直有这类问题?

### 根本原因

1. **简单字符串替换的局限性**
   - 脚本使用正则表达式进行全局替换
   - 无法理解 JavaScript/TypeScript 的语法结构
   - 无法区分不同的代码上下文

2. **批量处理的权衡**
   - 为了快速处理 173 个文件
   - 选择了自动化而不是手动翻译
   - 牺牲了准确性换取速度

### 正确的做法

理想情况下应该使用 **AST (抽象语法树)** 解析器:

```javascript
// 使用 @babel/parser 和 @babel/traverse
const parser = require('@babel/parser');
const traverse = require('@babel/traverse').default;

// 解析代码
const ast = parser.parse(code, {
  sourceType: 'module',
  plugins: ['typescript', 'jsx']
});

// 遍历 AST 并智能替换
traverse(ast, {
  StringLiteral(path) {
    // 检查上下文,智能决定如何替换
    if (isInObjectLiteral(path)) {
      // 替换为 t("key")
    } else if (isInJSXAttribute(path)) {
      // 替换为 {t("key")}
    }
  }
});
```
